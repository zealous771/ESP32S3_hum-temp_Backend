# AI 层（Phase 8 / Phase 9）

**当前状态：占位，本轮不实现。**

设计文档把 AI 排在最后。§42「现在不要做的事情」里明确列着 ❌AI ❌LSTM，
理由是 §26 的第一原则：

> **先有数据，再训练模型。**
> 不要在没有历史数据时直接训练 LSTM。
> 建议先积累：至少几天 / 最好几周 的真实传感器数据。

## 实现顺序（每一版都能独立验收）

| 版本 | 文档 | 内容 |
|---|---|---|
| 第一版 | §27 | 规则检测：温度 `<0/>50`、湿度 `<5/>95`。文档自己说"这不算真正的 AI" |
| 第二版 | §28 | 变化率：新增特征 `delta_temperature`、`delta_humidity` |
| 第三版 | §29 | Rolling Z-Score：`z = (x - mean) / std`，窗口约 30 分钟 |
| 第四版 | §30 | Isolation Forest，特征清单见 §30 |
| 预测 | §31 | 先树模型 / 梯度提升，深入再做 GRU / LSTM / Transformer |

## 两条硬约束

**1. 时间序列绝不能随机切分（§32）**

必须按时间序切：前 70% Train / 中 15% Val / 后 15% Test。
随机切分会让模型"看到未来"——离线指标好看得上天，上线就废，
而且这个错误从指标上看不出来。

**2. AI 的输出格式在 §33 已经定死了**

```json
{"device_id": ..., "ts": ..., "metric": ...,
 "anomaly_score": ..., "is_anomaly": ..., "reason": ...,
 "prediction": {"t+5m": ..., "t+10m": ...}}
```

`Web 页面直接使用这套数据`（§33 原话），所以这个结构不要改。

## 数据从哪来

`anomalies` 和 `predictions` 两张表在 v0.6-database 就已经建好，
对应的 API 路由（`/api/anomalies`、`/api/predictions`）也已经就位——
本轮它们返回空列表，等 AI 层开始写入数据就自然有内容了。

这是有意的：把"表结构和接口形状"与"算法实现"解耦。
算法可以换（规则 → Z-Score → Isolation Forest），接口不用动。
